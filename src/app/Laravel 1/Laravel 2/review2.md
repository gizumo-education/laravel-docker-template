## Todo論理削除

### traitとclassの違いとは
→クラスの継承とは異なって、トレイトは一つのクラスに複数のトレイトを追加することができる
→トレイト自体はインスタンス化できない

### traitを使用するメリットとは
→複数のクラス間で共通する処理を再利用可能にすることが出来る。
  クラスの責務を分割しやすい。
  名前の競合も対処できる。


## その他

### TodoControllerクラスのコンストラクタはどのタイミングで実行されるか
→ルート経由でコントローラーのアクションが呼び出されたときに自動的に実行される

### RequestクラスからFormRequestクラスに変更した理由
→バリデーション処理をコントローラーでしなくていいので、コントローラー内のコードがスッキリする
→同じバリデーションルールを複数の場所で使いたいとき、再利用しやすい
→テストがしやすくなる

### $errorsのhasメソッドの引数・返り値は何か
→has() メソッドの引数は、バリデーションエラーを確認したいフォームの「フィールド名（文字列）」
→返り値は 「true または false」 の真偽値。
該当のフィールドにエラーがあれば → true
なければ → false
→エラーが「あるかどうか」チェック

### $errorsのfirstメソッドの引数・返り値は何か
→first() の引数は、エラーメッセージを取得したいフォームの「フィールド名」（文字列）
→フィールドにバリデーションエラーがあれば、最初の1件のエラーメッセージ（文字列）を返す。
エラーがなければ null を返す。
→最初のエラーメッセージを取得。

### フレームワークとは何か
→プログラミングでよく使う処理を効率よく決まった形で実装できるようにサポートしてくれるソフトウェアのこと
  フレームワークを使うことで開発が早く、ミスも減り、コードが綺麗に保てる。

  PHP→Laravel
  JavaScript→React
  Python→Django
  Ruby→Ruby on Rails

### MVCはどういったアーキテクチャか
MVCは「アプリケーションの役割を3つに分けて設計するアーキテクチャ」
→M(モデル)、V（ビュー）、C（コントローラー）

### ORMとは何か、またLaravelが使用しているORMは何か
→ORM（Object-Relational Mapping）
  プログラミング言語の「オブジェクト」と、データベースの「リレーショナル（表形式）データ」を結びつけて操作しやすくする仕組みです。
  Laravelが使用しているORMはEloquant(エロクアント)

### composer.json, composer.lockとは何か
composer.json→プロジェクトが依存しているパッケージ（ライブラリ）の一覧やバージョン指定を記述したファイル
→どんなパッケージを使うか、バージョンの範囲を管理する設計図のようなもの

composer.lock→実際にインストールされたパッケージの正確なバージョンや依存関係を記録したファイル
→composer install 時に生成・更新される

### composerでインストールしたパッケージ（ライブラリ）はどのディレクトリに格納されるのか
→composerでインストールしたパッケージは、プロジェクト内の vendor ディレクトリに格納される。
